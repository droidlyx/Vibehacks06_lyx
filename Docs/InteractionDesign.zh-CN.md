# 对话主导的 NPC 交互设计（简化版）

日期：2026-10-31。状态：原始交互设计草案，部分机制已进入当前源码，尚未完成玩法验收。本方案替换此前的环境协作设计；不制作撑枝、搬运分工、合作机关或复杂契约。

当前源码已加入角色人设、附近发言、回应筛选与队列，以及警告后的规则行动；实际居民选择已扩展到角色库中的 20 个类型。下文六位早期角色及交互场景保留为设计参考，不代表每项情境都已实现或验证。当前运行链路见 [按需对话与持续行为](ConversationRuntime.zh-CN.md)，角色选择见 [角色设计库](CharacterCatalog/README.md)。

## 1. 核心体验

每个 NPC 有稳定的人设和利益，会根据眼前情况主动搭话。玩家与 NPC 的相对体型改变语气、提议和行动倾向；几种简单行动让对话产生实际后果。

循环：NPC 注意到玩家或现场变化 → 主动说一句话 → 玩家回应或离开 → NPC 继续商量或采取简单行动 → 这次经历成为下次对话的背景。

玩家不需要学习新的环境操作。互动重点是理解人物、判断意图、回应威胁、寻求保护，以及选择是否介入居民间的冲突。

## 2. 每个 NPC 的设定

下表是建议设定，沿用现有人物和动机，不新增人物资产。

| NPC | 性格与说话方式 | 最在意什么 | 典型行为倾向 |
|---|---|---|---|
| 米芽 | 温和、热心，有底线；话短，常问对方是否需要帮助 | 弱小者的安全与采食机会 | 主动关心弱小玩家；信任后跟随、保护；看到玩家欺负其他人会质疑、拒绝继续保护 |
| 陶恩 | 精明、务实，习惯谈条件；尽量避免无收益冲突 | 自己的食物、交易是否兑现 | 主动提出食物交换；打不过时商量，遇到混战优先自保；不会因一次拒绝就攻击 |
| 岚石 | 强势、直白，重视尊重与实际实力 | 领地、储粮和自身威信 | 对陌生小玩家发出警告；对大玩家更谨慎；认可后提供保护，不轻易承诺永久效忠 |
| 荒枝游民 | 胆小、饥饿时投机；试探多、硬话少 | 少量眼前食物与脱身机会 | 先讨要；对孤立且较弱的目标可能偷抢；面对强者或护卫倾向退开 |
| 赤背掠夺者 | 贪婪、好斗，善于欺软怕硬 | 别人携带的食物 | 向较弱目标索取或抢夺；被拒后可能开打；发现玩家有强大伙伴会重新评估 |
| 古岩守卫 | 寡言、警惕，警告明确 | 自己附近的空间与安宁 | 先警告靠近者，遭攻击或持续挑衅才反击；对玩家与其他 NPC 使用相同边界 |

人格需要稳定：一次体型变化可以改变谨慎程度，不能让温和角色突然变成无缘由的强盗。首版每人只需一段人设、一个主要动机和一条行为底线，不必制作完整背景传记或多维性格系统。

## 3. 大小怎样影响对话

用玩家体型/NPC体型形成“小于我、与我接近、大于我”三个区间；初始可试 0.75、1.3 两个边界，最终由人工体验调整。记录上次对话区间，避免边界附近每次说不同话。

给模型明确提供：双方当前身高、相对大小、上次见面时的体型、目前健康和食物、双方已发生的实际行为、附近正在攻击谁。

| NPC | 玩家比他小 | 玩家比他大 |
|---|---|---|
| 米芽 | “你还这么小，别一个人往那边走。” | “你现在能挡住它了，要不要帮帮还没长大的那些人？” |
| 陶恩 | “要几份口粮？先把交换条件讲清楚。” | “你能护我一阵，我可以拿食物交换。” |
| 岚石 | “这里的粮食有人看着，先说你来干什么。” | “我知道你比我强，但我们可以把条件谈清楚。” |

上述只是语气示例；提到保护、交换或具体人物前必须有对应真实条件。体型只是因素：受伤的大玩家未必强，带护卫的小玩家未必好欺负；曾经帮过或攻击过谁也会影响态度。

## 4. NPC 什么时候主动说话

先由规则选出附近的候选，再由 StartLux 判断是否相关/值得开口，通过后才排队调用 DeepSeek 生成一句话及一个可选行动。

- 初次靠近：根据人格打招呼、询问或警告。
- 玩家明显长大：再次见面时评论变化，并调整提议或态度。
- 自己缺粮、玩家有粮：讨要、交换、索取或威胁，具体方式由人格和实力关系决定。
- 玩家受伤或被攻击：友好 NPC 提醒、询问是否需要保护；已有保护关系则直接执行既有援护规则。
- 刚发生分享、抢夺、战斗或救援：作出针对这件事的回应。
- 附近两个 NPC 有冲突：当事人警告、求援或解释，玩家可以介入、劝停或离开。

每名 NPC 有主动发言冷却；同一事件不重复请求模型，附近同一时刻只突出一个主动发言。最新建议为 NPC 对玩家每人60–120秒、NPC之间每对120–240秒、全局主动事件至少20秒间隔，具体以[运行规格](ConversationRuntime.zh-CN.md)为准。战斗受击反馈不受此限制；没有新情况就保持安静，不做持续轮询式聊天。

主动发言用头顶短句和“按 T 回应”，不强行弹出对话框或抢走操作。玩家离开不等于挑衅。玩家正在阅读对话时，说话者不能突然发动由该轮模型提议产生的攻击或抢夺；先结束对话、给出明确警告与短反应时间。第三方已有战斗仍由现有中断机制处理。

## 5. 只保留少量可执行行动

现有分享、供奉、政策动作可继续保留，本轮新增互动的重点只放在下表。`none` 表示只说话或拒绝，不改变世界。

| 行动 | 最简单的实现含义 | 可见反馈与边界 |
|---|---|---|
| 攻击目标 | 指定一个存活角色，交给现有追击/攻击逻辑 | 模型不直接扣血；主动寻衅先警告，实际命中才扣血 |
| 保护玩家 | 跟随玩家，攻击正在伤害/威胁玩家的敌人 | 复用已有援护；危险过大可撤退；不替玩家攻击一切路人 |
| 单纯跟随 | 跟随到玩家附近，不主动介入无关战斗 | 与“保护”区别明确；自身受击仍可自卫 |
| 抢走食物 | 靠近玩家后尝试一次真实转移 | 初版每次至多 1～3 份且不超过现存食物；有距离和冷却；明确显示谁抢走多少，不能隔空扣粮 |
| 停止/离开 | 清除本次跟随、保护或主动攻击意图 | 玩家可以赶走同伴；受击仍可重新自卫 |
| 停战 | 对本次交战对象结束敌对状态 | NPC 不能用一句话替第三方同意停战；双方各自条件须满足 |

“抢夺”一开始不制作潜行系统或偷窃小游戏。可以用接近、短抢夺动作和资源提示表现，玩家可通过移动离开或已有护卫阻止。一次转移只执行一次；重发、迟到回复不能重复扣粮。抢夺后没有无限追抢循环。

## 6. NPC 之间也会战斗

攻击使用角色目标 ID，目标可以是玩家或另一个 NPC，复用同一套战斗。现有角色已经能发生野外生物与居民交战；本轮补的是人格、具体动机、主动对白和目标选择，使冲突更容易理解。

初版只有三种明确原因：

1. 自己或正在保护的人受到攻击，产生自卫/援护。
2. 掠夺型 NPC 在缺粮、对方明显较弱等条件下发出威胁并升级冲突。
3. 领地型 NPC 已警告，另一角色继续明确挑衅或侵犯受保护的对象。

首版先接 1、2，第三种等有明确可判定的侵入行为再补；不能把两人普通路过算作挑衅。不因为一句随机生成的辱骂就让全谷开战。

示例：赤背掠夺者威胁小玩家 → 玩家向岚石求助 → 岚石愿意保护 → 赤背可能退让，也可能与岚石交战 → 玩家可以参战、离开或之后致谢。玩家长大后再次遇到赤背，它可能改口；它记得的是实际战斗和抢夺结果，不是凭空编出的故事。

对普通争执优先警告、退让和停手，不默认所有冲突必须打死一方。没有模型请求时，实际战斗、自卫和撤退照常运行。首版不做派系战争、多人联合谈判或全局口碑传播。

## 7. 最少需要补的系统

- 人物资料：在现有 Motivation 上增加简短人格与行为底线。
- 主动搭话：一个触发原因、每人冷却、上次体型区间、已处理事件标记。沿用每 NPC 对话历史和同一请求队列。
- 对话输出：沿用 say/action/target/amount，不另造复杂协议。玩家回应与NPC主动发言需要区分上下文：现有“只能执行玩家明确请求”规则继续用于玩家请求；主动上下文只允许该触发原因对应的有限行为。
- 同伴模式：区分纯跟随与保护，复用 FollowId 和现有援护逻辑。
- 行动执行：增加主动攻击目标、近距离抢夺、停止和有明确对象的停战。每次执行再次检查身份、距离、库存、伙伴关系和请求时的情况是否仍成立。
- 简短事实记忆：最近一次真实帮助、攻击、抢夺，以及最近一次见面的体型；用现有事件记录与历史即可先实现，暂不做长期记忆数据库。

运行架构以[按需对话与持续行为规格](ConversationRuntime.zh-CN.md)为准：只有距离范围内的发言会被收听；StartLux先筛选与自身是否相关，通过后才按预算调用DeepSeek。主动NPC-玩家与NPC-NPC对话使用同一流程。对话只低频改变行动意图，日常逻辑持续执行；等待模型不停止角色，`none`不清空现有计划。StartLux现在是必要的相关性门控，不再仅是可选次要选择。模型失败时保留现有行动，不生成虚构对白或新增敌意。

## 8. 让对话自然带出共同目标

### 一个长期方向，一件眼前的事

保留已有“母树复苏”作为共同远景，由居民在对话里表达各自支持、担忧或拒绝的理由。眼前目标来自同一件牵动多人利益的事，而不是给每个人分配一条独立跑腿清单。

玩家可以在对话中答应帮忙、提出别的办法、暂不承诺或直接离开。听说事情不等于接下请求；没有答应不算失约。界面只在现有手记里保留一句明确的约定和当前事实，例如“陶恩：请陪我把这5份粮送到母树”“还在等安全的出发机会”，不反复显示命令式目标。目标不能因表达自然就含糊到玩家不知道自己答应了什么。

### 预设少量人物关系

第一版固定以下关系，作为开局背景写入角色资料；后续只记录游戏中确实发生的改变，不让模型自行编造旧账：

- 米芽曾帮助过陶恩，关心他，也希望他能参与复苏母树。
- 陶恩依赖岚石的威慑，但不满岚石总要他出粮，因此不愿直接向他求助。
- 岚石认为陶恩只在遇到危险时找自己；他与赤背有冲突，但没有无条件保护陶恩的承诺。
- 赤背了解陶恩的畏战，倾向威胁落单的陶恩；面对岚石会更谨慎。

这里是人物态度，不建立债务、利息、保护费结算等额外经济系统。每个 NPC 的主动请求来自这些关系和当前处境的交集。

### 首个共享事件：陶恩这次不敢送粮了

事件只有在陶恩存活、有实际可供奉余粮、母树未复苏，并且存在附近敌对威胁或最近受袭记录时才成立。不能在库存不足时假装有一批待送粮，也不能仅因赤背还活着就认定道路危险。

玩家从任意一人处都可以进入同一事件，无须按顺序挨个谈话：

| 说话者 | 自然带出的信息与请求 |
|---|---|
| 米芽 | “陶恩留了些粮给母树，可赤背又在附近。他不肯找岚石，你能去陪陪他吗？” |
| 陶恩 | “我愿意送这几份。但得有人让我走得出去。你陪我，还是能让赤背别来找事？” |
| 岚石 | “他不肯来找我，倒让你来了。赤背要是真动手，我也有账要跟它算。” |
| 赤背 | 可以索粮或警告，暴露自己的目的；是否愿意退让取决于实力与当前实际关系 |

这些话是示例，不是固定脚本；只允许引用角色已知的实际情况。前两者已经表达清楚“帮助一个人完成一次真实送达”这个共同目标。岚石和赤背提供可选解法，不各自再塞给玩家一项前置琐事。

玩家可以自己陪同并打退威胁；说服岚石加入保护；与赤背商量、分享少量实际食物换一次退让；也可以先成长后凭实力威慑。小玩家更容易选择借助关系，大玩家可以自己承担保护，但任何体型都保留不同选择。威慑的结果仍需落实为停战或撤退，不能把一句“我怕你了”当成安全。

实际操作只用说话、跟随、保护、攻击、停战、食物转移与已有供奉。保护/跟随的目标允许使用 NPC ID，这只是把已有行为指向陶恩；不增加搬运玩法、复杂队伍系统或必须完成的环境机关。

玩家也可以拒绝、站在赤背一方或抢走食物。由此获得的资源仍能推进自己的成长或母树，但不算完成“保护陶恩送达”的承诺。失败一个请求不终止整个游戏。

### 成功、变化与归因由实际世界决定

承诺一旦接受，就记录本次参与者、约定数量和起点。首版可复用已有 DonationPledge、供奉记录、存活状态及本次事件 ID；不需要自然语言任务生成器。

| 实际变化 | 请求如何处理 |
|---|---|
| 陶恩仍活着，约定粮食实际计入他的供奉 | 本次送达完成；嘴上答应、开始走路都不算完成 |
| 赤背被其他 NPC 击败、撤走或双方停战 | 去掉已消失的威胁，不再要求玩家杀死它；仍可完成送达 |
| 果林恢复、陶恩自行获得足够粮食 | 不再沿用“缺粮”的请求理由；已有送达约定是否需要保护仍按现实判断 |
| 储粮被抢、用于恢复，或保护者受伤离开 | 当前计划受阻，角色说明事实；可重新谈数量或办法，不默默改变玩家已答应的目标 |
| 供奉过程中母树剩余需求减少 | 以母树实际还能接收的养分为上限，余粮留在持有者手中，绝不为旧数字强行扣粮 |
| 母树已经由别人复苏 | 原供奉请求已经没有必要，正常结束；不给玩家虚构送达功劳 |
| 陶恩死亡 | “保护他送达”的承诺失败；玩家捡粮自行供奉是另一种结果，不能算救人成功 |
| 玩家接下请求前事情已自行解决 | 不再发请求，只说发生了什么；没有交任务和刷奖励环节 |

事件在世界里解决，与玩家有没有贡献分开记录。实际保护、赠粮或促成有效停战才构成对应帮助；旁观结束可以听到感谢事情结束的对白，但不自动得到帮助者待遇。同一笔食物转移、同一次送达和同一个事件只结算一次。事件完成后冻结这次结果，后来发生的新冲突不倒扣已完成请求，也不因反复切换权限/敌对状态而刷新奖励。

首轮回报主要是 NPC 对玩家的具体态度变化，例如陶恩更愿意分享余粮或同行、岚石承认玩家承担过风险。任何食物回报都从实际库存扣除，不增加任务金币或凭空经验奖励。

### 保持实现简单

第一轮只制作上述一个共享事件，并用“听说、已答应、进行中/受阻、已解决/失败/不再需要”几个状态表达。最多跟踪一个玩家已答应的主要请求。

后续如需要扩展，只增加另一种模板“让某人解除眼前缺粮”：真实赠粮、抢回已有粮食或让他获得采集资格并实际采到粮，都可以产生不同解法。它应服务于同一人物矛盾，不能变成每人一份固定材料清单。

规则负责决定事件是否存在、当前可选办法、成功和失效；DeepSeek 把这些事实表达为符合关系与体型的对白。模型可以提出已有模板内的请求，不能自行添加未实现的收集物、机关或成功标准。

## 9. 实施优先级

第一步：六个人物设定、少量预设关系、主动搭话触发、体型相关对白。先让玩家认得出他们、感到他们会注意自己。

第二步：区分跟随/保护，复用 NPC-NPC 战斗，并只串起“陶恩这次不敢送粮了”这一件共同事件。目标、回应和完成判定都落到真实状态。

第三步：加一次性近距离抢粮，让已有事件能够因库存变化受阻或改谈；调整冷却和频率，避免玩家被不断骚扰。

人工体验重点：玩家是否能从对话理解共同目标；是否必须逐个做琐事才能推进；不同体型能否采用不同办法；环境变化后 NPC 是否还在重复过时请求；成功和失败是否与亲眼看到的事情一致。由用户亲自试玩，本轮不运行测试。
