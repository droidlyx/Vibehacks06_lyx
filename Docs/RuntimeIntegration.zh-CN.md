# 20人场景、对话与成长接入记录

日期：2026-10-31。当前工程：`VerdantAccord_v03`。本轮修改运行代码和所需资产，没有合并发布或重新打包历史Windows构建。

## 本轮接入

- 20个不同Titan模型，0.3～10米对数分层身高，固定种子分配。各自有类型、人设、动机、名字、库存和关系。
- 启用角色库中11类基础/专属关系；匹配角色白名单，限制方向、互斥、每对/每人数量。其余关系仍为设计储备。
- 一个多人共同事件：陶恩接受真实送粮计划后，以其实际供奉记录、生存及母树状态判定完成、受阻、失败或失效。
- 玩家发言只进入20米范围内听众队列；StartLux判断相关后才调用DeepSeek。背景对话也通过同一门控。初版串行调用，每条自动链最多两句，不循环调用模型维持行动。
- 规则持续执行采集、跟随、保护、战斗和撤退；模型等待不暂停角色。攻击/抢粮有动机检查、预告、延迟复验和冷却。
- 160个四档食物点，前24个在起点附近且为第1档；可部分获取，残余不降档、不回满。全场每30秒按开局各档对象数量补回采空或缺失的食物点，新增位置在原所属区域内重新随机选择。
- 玩家容量、NPC供粮、抢夺与尸体拾取使用统一档位/容量检查。NPC之间也不能把高档食物转交低档角色降档中转。果林内食物保留准入与真实分成。
- 只有玩家每5秒自动成长。NPC可以使用食物恢复生命，但不会成长。
- 玩家死亡后2.5秒自动回安全起点，身高保留85%，不低于当前18厘米起步；保留新容量以内的食物，溢出留在死亡处并保持原档位；复活后保护3秒。世界、人物关系和已完成进度不重置。

## 当前默认参数

参数集中在 `Source/Verdant/VerdantEconomyRules.h`；初始玩家尺寸继续使用用户已有的 `VerdantPlayerScale.h`。

| 项目                 | 当前实现                                                                                                                              |
|----------------------|---------------------------------------------------------------------------------------------------------------------------------------|
| 地面食物档位与初始量 | 1/2/3/4档：1/3/8/20份，即原始价值的1/5；内部保留小数                                                                                  |
| 初始食物点           | 保持160个，其中24个起点附近第1档食物点                                                                                                |
| 后续补充             | 全场每30秒补回已采空或缺失的初始食物点，使各档仍有食物的对象数量恢复为开局数量；重新随机选点，保留档位、果林归属和起点区域分配        |
| 补齐口径             | 按食物对象数量，不按养分总量；未采空的对象保持原位与剩余量，部分剩余不补满；死亡掉落不计入初始数量，也不再生                          |
| 随机落点             | 检查实际地面、45度以内坡面、障碍和食物间距；有限次采样找不到安全位置时保留缺额至下一轮，日志 `VERDANT_FOOD_REFILL` 记录各档新增与缺额 |
| 解锁身高             | 1档无门槛，2/3/4档为1.2/2.0/3.2米                                                                                                     |
| 玩家容量             | `20 * max(1, 身高厘米/81)^2`，最低20                                                                                                  |
| 自动消耗             | 每5秒消耗当时库存20%；内部保留小数                                                                                                    |
| 成长换算             | 新身高为 `cuberoot(当前身高^3 + 实际消耗 * 81^3/20)`，上限4.5米                                                                       |
| 生长空间不足         | 本次不消耗，待下一轮有空间再长大                                                                                                      |
| 起始体型             | 保留用户现有18厘米及其速度配置                                                                                                        |
| 主动对话             | NPC向玩家60–120秒，NPC配对120–240秒，全局主动间隔20秒；须有实际新情况                                                                 |
| 本地门控失败         | 不调用云端，保留原行动并显示状态                                                                                                      |

成长/复活数值是本轮可调初值，不是最终平衡结论。母树目标仍保留100份；后续可结合人工体验调整整体供给和公共目标。

## 启动与操作

最新DLL已完成冷编译链接。使用根目录 `Open-Editor.cmd`
打开，再由用户手动Play。该入口在后台启动StartLux相关性服务，并为编辑器准备DeepSeek配置。直接打开uproject时，请另行运行
`Start-SecondaryAI.ps1`。

- E：获取附近食物/尸体食物，满容量或档位不足时保留原数量。
- T：打开附近居民对话；其它处于听觉范围内的NPC也可能相关并回应。
- F：按现有规则分享或供奉。Q不再额外消耗，只提示自动成长时间。
- 正常死亡会自动复活；R仍是明确手动重开整局。

`Local/Secrets/deepseek.key`不进入源码或便携包。StartLux默认路径使用当前电脑已有模型和Python环境，见 `Docs/LocalAI.md`。
