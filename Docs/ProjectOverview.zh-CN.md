## 1. 总体设计：成长提供力量，行动决定世界

最初的方向是“由 NPC 的行动推进剧情，而不是依赖传统任务线”。随后加入了“不同大小的生物共存、玩家连续长大、自然地形在不同尺度下有不同体验”的构想。

当前原型把二者结合为一个可观察的资源社会：居民有自己的食物、体型、领地和行为，玩家可以改变他们的处境。成长让玩家有更多选择，但母树复苏时，游戏记录的是整个山谷的变化，而不只是谁变得最大。

| 设计问题                   | 当前选择                                                                                             |
|----------------------------|------------------------------------------------------------------------------------------------------|
| 素材少，如何表现世界尺度？ | 使用约400米宽的自然山谷、远近地形与大小不同的树石；同一套角色随体型连续变化，环境成为稳定参照。      |
| 场景搭建能力有限怎么办？   | 地形、道路、空地、母树和资源植物由代码生成，少量树石草反复组合；不做城镇与复杂建筑群。               |
| 为什么要长大？             | 更大的生命、力量和攻击范围；体型也能成为谈判筹码。成长消耗可用于其他目标的食物。                     |
| 如何避免只有战斗一条路？   | 允许采集、赠送、养护、供奉、请求居民协助、和平接管和自由战斗。                                       |
| NPC 如何推进事情？         | 采集、搬运、避敌、迁移、跟随与援护是实际行动；路途中可能受阻，承诺不等于已经完成。                   |
| 结局为什么会不同？         | 同样复苏母树，可以留下公共开放的山谷，也可以形成玩家收取分成的领地；居民生死、控制权与生态分别记录。 |

**范围边界：目前不是无限世界，也不是任意尺度下自相似的分形地形。**
当前是有限山谷和有限成长范围，用来验证“尺度变化＋社会选择”的核心体验。分形递归、跨数量级探索和更丰富的自然生物仍属后续方向。

## 2. 当前可玩的核心循环

### 2.1 食物、成长与战斗

基本循环是：探索 → 采集或战斗获取食物 → 决定食物用途 → 改变自身与居民关系 → 获取新的资源和行动空间 → 推动母树复苏。

玩家初始身高约 **0.81米**，当前上限约 **4.5米**。按 Q 食用5份食物后，养分逐渐转化为成长，不会瞬间跳到一个新体型。角色碰撞、落地与镜头需要随体型适配；HUD
显示初始与当前身高参照。

战斗包含轻击、重击、闪避、受击与死亡。体型直接影响生命、伤害和攻击范围；命中按实际时机和方向判定。击败生物后只能拾取它真实持有的食物，不会额外凭空生成战利品。v0.3
增加了攻击方向提示、实际伤害数字及一次有限的收招输入缓存。本轮主角表现改为简洁的蓄力碰撞／砸击，动作冲击点对齐既有攻击进度
0.60 的伤害时机；手感与可读性待用户试玩。

同一份食物可以用于自己成长、治疗、赠送、养护土壤或供奉母树。选择之间有真实成本，因此“继续变大”不是唯一合理用途。

### 2.2 自然场景与尺度感

世界包含三片果林、一棵母树、三位主要居民和三位野外生物。本轮以三种 Titan 卡通生物替换旧人形表现：编号 1、3 使用小企鹅，2、5
使用哑光豆豆猫，4、6 使用沙漠鼬；居民与野外生物仍沿用现有行为和资源规则。

地形以碗状山谷、坡地、宽阔通路和局部空地组织。通路减少细碎起伏，居民与目标周围留出活动空间；树石根据网格边界统一尺寸、贴合实际地表。地形和环境在运行时生成，编辑器中点击
Play 后才出现完整场景。

当前尺度感依赖稳定的树石参照、体型差异和连续成长，并不等于已经证明广阔世界探索足够有趣。增加跨尺度地标与探索奖励仍是重要提升方向。

### 2.3 NPC 自主行为与自由协商

三位主要居民分别是米芽、陶恩与岚石，对应不同的果林准入政策和食物保留需求。日常行动由游戏规则驱动，自由文本协商由配置的 DeepSeek 云端模型参与。

已实现的行为包括采集、进食成长或恢复、危险规避、迁移、实际搬运供奉、跟随、同伴援护和使用富余粮食养护土地。移动遇阻时会尝试绕行或暂时放弃目标，避免持续朝同一障碍前进。伙伴不会自动攻击同队角色；遭外人袭击不会直接忘掉跟随约定，被领队攻击则会结束约定。

当前源码通过 `https://api.qnaigc.com/v1` 调用 **DeepSeek V4.1 Flash 1017**（`deepseek/deepseek-v4.1-flash-1017`），需配置自己的 API 密钥并承担调用费用。启动器不再自动启动 Qwen，也不将其作为回退；历史 v0.3 可玩包仍使用 Qwen3-1.7B Q8_0 + llama.cpp。StartLux 仅保留按需启动入口，尚未接入 NPC 周期行为。配置见 [LocalAI.md](LocalAI.md)。

玩家可以自由输入，但可执行行为有明确范围，包括赠粮、开放或限制果林、设置分成、实际供奉、跟随、迁移、停战和和平移交控制权。

游戏会向模型提供当前合法行动及条件，再对结果检查权限、距离、资源与目标是否存在。NPC
的对白与“实际执行了什么”分开显示。承诺将来帮助、重复请求或模型声称已经付款，都不会直接增加资源或贡献。

v0.3 的协商会参考玩家已完成的养护与供奉、实际净赠粮、体型以及居民自身的粮食储备。每名 NPC 保留独立对话历史；延迟回复不会串到另一个
NPC 的窗口里。模型仍可能误解或拒绝，尚不支持任意自然语言契约。

### 2.4 能改变整个世界的选择

母树累计收到 **100份养分** 后复苏。它是共同里程碑，不是最终大 Boss；复苏后世界仍继续运行。

- **养护**：在有权限的果林按 B，最多花5份食物改善土壤；每份增加3个百分点肥力，满肥力不扣粮。
- **公共开放**：通过实际帮助和协商，使居民继续持有果林并允许免费采集。
- **和平管理**：协商让居民移交果林，居民仍然活着；玩家用 G 在免费、30%分成、限制采集之间切换。
- **武力干预**：可以攻击居民或野外生物，死亡会中断行动并改变资源与控制关系。

复苏时保存本季记录：居民与野外生物存活、免费开放果林数、玩家领地、各人的实际供奉、土地生态及养护投入。之后的变化不覆盖这一历史记录。

两条已验证的正常资源路线如下；这是实际回放结果，不是预设的结局按钮：

| 观察项           | 公共开放路线       | 和平接管路线       |
|------------------|--------------------|--------------------|
| 母树养分         | 100，已复苏        | 100，已复苏        |
| 主要居民存活     | 3/3                | 3/3                |
| 野外生物存活     | 2/3                | 2/3                |
| 免费开放果林     | 3/3                | 0/3                |
| 玩家管理果林     | 0处                | 2处，均收30%分成   |
| 高地果林         | 岚石持有，免费开放 | 岚石持有，限制采集 |
| 报告末尾土地生机 | 100%               | 100%               |

两条路线的社会结果确实不同，但生态结果在这两次验证中相同。当前支持生态变化的机制，不代表已经验证出多种长期生态演化故事。

## 3. 美术风格与实际资源

视觉方向是温暖、低细节、哑光的林地寓言：苔绿与鼠尾草绿、砂岩暖色、琥珀色养分、柔和远景。强调容易读懂的轮廓和一致材质，避免大量写实细节与复杂建筑。

**目前没有使用任何付费 AI 生成的3D模型。** 本轮角色由原创程序造型和本地 Project Titan 素材组成；自然模型继续使用原有
Quaternius CC0 素材。Titan 内容保留适用的 Epic／Project Titan 条款，不属于 CC0。

| 类别         |             数量 | 实际来源与用途                                                                          |
|--------------|-----------------:|-----------------------------------------------------------------------------------------|
| 主角         |              1套 | 原创程序化种子／嫩芽球形生物，以挤压、回弹和简洁碰撞／砸击表现动作。                    |
| NPC 骨骼角色 |              3种 | Titan 小企鹅、豆豆猫、沙漠鼬，分别用于编号 1/3、2/5、4/6。                              |
| 当前生物动作 |   按各自骨架制作 | 烘焙简单动作；豆豆猫原附动作与模型使用不同骨架，不能直接认定兼容。                      |
| 历史人形资源 | 3套模型、9段动作 | Quaternius Traveler、Gatherer、Keeper 及 UAL 动作保留归档，当前运行时角色表现不再使用。 |
| 自然静态模型 |              6个 | Quaternius Nature MegaKit：2种树、3种石头、1种草。                                      |

Ember 的游戏源码、地图、蓝图或已制作 UE 资产；Ember 只作为设计参考。

调研文档已覆盖鉴权、任务提交、状态轮询、下载、余额、绑定/动画、网格处理和主要计费差异。它是后续实施参考，不代表三个生成流水线都已完成付费实测。尤其是账户
API 权限、绑定效果、动作兼容性和最终导入质量，仍须用一个完整样本验证。

本次补查确认：Tripo Studio 已提供文本生成动作及多段动作拼接，官方教程描述最长10秒；公开 API 仍主要提供预设动作重定向。V2fun
提供动作库检索、重定向和视频人体动捕；Hyper3D 提供多类骨架及预设／上传动作。它们均不能直接证明任意非人形的攻击动作可用。此轮先复用
Titan 模型并制作简单动作，未产生外部费用，详见下方接口文档中的官方来源。

如后续确需生成，优先补有明确玩法作用的缺口：具有鲜明轮廓的新生物或核心地标。角色家族尽量保持单一供应商和模型版本，避免不同站点产生不一致的材质与身体比例；跨供应商工作优先分配到不同资产类别。先验证一个样本，再决定是否批量生成。

详细接口和预算控制见 [GenerationAPIs.md](GenerationAPIs.md)

CSV 采样存在退出异常，已记录且正式验证未开启；没有通过隐藏异常来宣称通过。

## 7. 待完成项与下一轮优先级

1. **优先做真实试玩。** 观察新玩家能否理解成长成本、果林权限与NPC承诺，记录前几分钟的停顿、迷路和重复劳动，再决定调参。
2. **加强“同一地点，长大后意义不同”。** 增加少量尺度参照与有用途的通路，逐步验证跨尺度玩法，再考虑完整分形世界。
3. **让居民之间持续有可见冲突。** 在现有资源与权限系统上增加有限的供需变化、互助或争夺，解决目前可能进入稳定等待的问题；无需先扩写大量固定任务。
4. **让世界差异更直观。** 将管理政策、资源压力与土地变化更多地反映在居民移动、果林外观和现场事件中，减少只读结果面板的负担。
5. **完善体验与稳定性。** 人工检查动画朝向与穿插、试听音效、测实际帧时间，继续验证超出既有回放路线的自由对话和操作。

尚未实现：无限/递归分形世界、无限成长、任意自然语言契约、完整剧情战役、存档与多人联机。新增生成模型不是当前前置条件；应先确认玩法和可读性确实需要新资源。
